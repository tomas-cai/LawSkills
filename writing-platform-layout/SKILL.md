# 平台化内容排版与阅读体验

把“写得正确”转换成“读起来舒服、看起来专业、愿意继续读”。平台排版不是把同一篇文章换个 CSS，而是根据平台的阅读场景重新安排信息层级、节奏和视觉重点；不得改变已经确认的事实与主旨。

## 核心原则

1. **阅读体验优先**：先保证读者能看懂、扫得动、读得下去，再追求装饰。
2. **美观必须可解释**：颜色、字号、留白、图片和强调都要服务于层级、节奏或理解，不能为了“好看”堆组件。
3. **平台原生感**：公众号不是博客，小红书不是缩短版公众号，头条不是把长文直接丢进信息流。
4. **视觉系统一致**：同一篇文章的标题、正文、引用、代码、表格、图片、图注和 CTA 使用同一套视觉规则。
5. **移动端先行**：默认按手机单列阅读检查；桌面端只是加宽，不反过来牺牲手机体验。

## 输入检查

读取以下输入：

- `revised-draft.md`：最终正文、标题和事实边界；
- `image-brief.md` 与 `images/`：图片用途、比例、alt、图注和状态；
- `style-rules.json/style-guide.md`：个人风格、品牌色和禁用项；
- `EXTEND.md` 或 `EXTEND.local.md`：平台、品牌、编辑器和交付约束；
- 用户指定的目标平台、读者、文章长度、发布形式和人工确认点。

先建立六格需求卡：问题、场景、输入、输出、规则、禁止。检查素材是否完整、图片是否真实存在、外链是否明确、是否存在表格/代码/二维码/敏感信息等需要特殊处理的内容。

## 工作流程

### 1. 选择阅读模型

先判断读者如何消费内容：

| 平台 | 默认阅读模型 | 首要目标 |
|---|---|---|
| 微信公众号 | 移动端连续长读，可随时停下来扫读 | 让读者顺畅读完，并记住关键观点 |
| 小红书 | 首图吸引，卡片逐页滑动，文案区补充 | 一页一个重点，快速理解并愿意收藏/互动 |
| 今日头条 | 信息流首屏判断，快速扫描重点 | 标题和首屏兑现承诺，降低跳出 |
| 博客/HTML | 可搜索、可跳读、可长期访问 | 结构清晰、链接稳定、桌面与移动端兼容 |

目标平台不明确时，先询问或采用公众号长文作为默认，并标记该假设。

### 2. 建立内容架构

把正文拆成阅读组件，而不是直接套标签：

- 标题、摘要/副标题、导语和首屏承诺；
- 一级/二级章节、章节导语和转场；
- 重点结论、引用块、警示、步骤、对比、表格和代码；
- 图片位、图注、alt 文本、来源；
- 小结、行动建议、CTA、原文链接和相关文章。

为每个组件写清“它帮助读者完成什么动作”。没有阅读任务的装饰组件不保留。

### 3. 设计视觉系统

先定义一套轻量令牌，再排全文：

- 内容宽度、左右边距、正文行高和段落间距；
- 标题层级、字号对比、字重和颜色；
- 正文、辅助文字、链接、引用、代码、表格、图注的颜色与背景；
- 分隔线、卡片、圆角、阴影和强调色的使用上限；
- 图片比例、最大宽度、上下间距和图文关系；
- 小屏下的换行、长词、数字、URL、代码和表格处理。

默认采用“一个主强调色 + 中性色层级”的克制方案。不得同时使用多种高饱和色、过多卡片、连续粗体或每段彩色高亮。

### 4. 按平台重新排版

**微信公众号**：采用移动端单列长读结构。控制段落长度和留白，使用清晰的 H2/H3、重点引用、章节导语、图片分隔和小结；表格过宽时改为列表/分组卡片，代码过长时改为横向滚动或截图并保留文本替代；不依赖编辑器不支持的复杂 CSS。

**小红书**：把文章拆成封面与卡片序列。每张卡只承担一个核心观点，文字少而醒目，先设计视觉顺序再压缩文案；正文 caption 承担背景、例子、补充说明和自然话题标签，不把长文原样塞进图片。

**今日头条**：优先优化信息流首屏。标题、首图和导语必须共同兑现正文承诺；把核心事实、步骤、数据或案例前置，减少长段落和过度装饰；关键词自然出现，不使用诱导性夸张标题。

**博客/HTML**：保留语义标题、目录、锚点、响应式布局、可复制代码、链接和基本可访问性；不把平台专属装饰写死在通用正文中。

### 5. 生成交付物

默认输出：

- `platform-layout.md`：平台、阅读模型、组件结构、视觉令牌和排版决策；
- `layout-manifest.json`：正文组件、图片 ID、位置、样式和状态的机器可读清单；
- `article.html` 或平台可粘贴富文本：按用户指定平台生成；
- 小红书额外输出 `cards/` 卡片文案与逐页视觉说明。

HTML/富文本必须使用本地或已确认的图片路径；需要内嵌时再转 base64，不默认引用不稳定远程资源。未生成、未确认或版权不明的图片不得出现在最终正文中。

### 6. 做视觉与阅读质检

渲染目标交付物，优先检查手机宽度，再检查桌面宽度。可使用当前环境可用的浏览器或 HTML 预览能力截图检查；仅看源码不算完成视觉质检。

依次做三轮阅读：

1. **3 秒扫描**：只看标题、首屏、图片、加粗和小标题，能否知道文章讲什么？
2. **30 秒理解**：只读导语、小标题、重点句和小结，能否复述主要观点？
3. **完整阅读**：段落是否疲劳、转场是否自然、图片是否打断理解、结尾是否完成行动闭环？

发现文字墙、视觉噪声、层级混乱、图片拥挤、留白失衡、表格溢出、代码不可读或移动端裁切时，先调整结构、间距和组件，不要直接缩小字号。

### 7. 设置人工确认

在以下节点停止自动推进并请求确认：平台选择、标题/封面最终方案、强调整体风格、敏感/版权内容、外链/二维码、正式发布前。默认只生成可审阅稿或草稿，不执行最终发布。

## 产物契约

`platform-layout.md` 必须记录：

- 目标平台、读者、阅读模型和关键假设；
- 标题/摘要/首屏方案；
- 文章组件树与每个组件的阅读任务；
- 视觉令牌、间距、颜色、图片和代码/表格策略；
- 平台特有的删改、拆分、重排和保留项；
- 视觉质检结果、问题截图/位置、未解决项和人工确认点。

`layout-manifest.json` 至少包含 `platform`、`content_blocks`、`image_slots`、`visual_tokens`、`metadata`、`qa` 和 `open_questions`。

## 质量门禁

使用 1–5 分评分，以下五项都至少 4 分才允许标记 `LAYOUT_READY`：

| 维度 | 检查重点 |
|---|---|
| 可读性 | 读者能扫读、理解、继续阅读，段落和句子不造成疲劳 |
| 视觉层级 | 标题、正文、重点、图片和 CTA 的优先级一眼可辨 |
| 美观度 | 留白、对齐、色彩、比例、节奏和一致性让页面显得专业而不拥挤 |
| 平台原生感 | 版式符合目标平台的阅读和互动习惯，而不是通用模板硬套 |
| 交付完整性 | 图片、链接、代码、表格、alt、来源和元信息均可用 |

出现以下任一情况，必须返回修改：首屏看不懂、正文形成连续文字墙、重点过多导致没有重点、图片只是装饰、移动端溢出/裁切、内容承诺被排版夸大、视觉风格与个人/品牌规则冲突。
