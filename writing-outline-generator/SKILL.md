# 写作大纲生成

把素材分析转化为“每一节为什么存在、凭什么成立、写完要让读者做什么”的文章骨架。大纲是 writer 的施工图，而不是文章正文。

## 输入检查

先建立六格需求卡，至少确认：

- 文章目的、目标读者、平台、文体和期望行动。
- `content-analysis.md` 或 `.json` 是否存在；没有素材分析时先要求补充，或明确按用户提供的事实直接工作。
- 风格规则、目标字数、标题限制、是否允许第一人称、是否需要 SEO 关键词。
- 主题范围与不做的内容，避免大纲越界。

## 工作流程

1. 提取主旨候选，选出一个能在一句话中表达“读者看完获得什么”的中心承诺；如果多个主旨互斥，分别生成方案，不强行合并。
2. 按“读者问题 → 解释/证据 → 选择/行动”的逻辑安排章节。优先使用素材中的证据 ID，不凭空填充案例。
3. 生成 2–4 个标题方向：信息型、问题型、结果型或平台适配型；对有标题党风险的平台说明承诺与风险。
4. 生成不超过三层的结构树。每个一级/二级章节写清：目的、核心观点、证据/事实 ID、例子或原话、转场、字数预算和完成标准。
5. 检查顺序、重复、跳跃、论点—证据匹配和结尾闭环；对于证据不足的章节标记 `NEEDS_SOURCE`，不得用空泛表达掩盖。
6. 输出 `outline.md`。若平台需要，可在同一文件中追加 HTML/SEO/图片位等交付备注。

## 产物契约

`outline.md` 至少包含：

- 写作任务卡：目的、读者、平台、文体、目标字数、主旨、CTA
- 标题备选及每个标题的承诺/风险
- 结构树（最大深度 3）
- 每个章节的“目的—观点—证据—例子—转场—字数—完成标准”
- 素材覆盖表：每个重要事实/观点在哪一节使用，哪些舍弃及原因
- 缺口、待确认项和下游写作注意事项

章节块使用以下格式，便于 writer 逐块生成：

```markdown
## 2. 章节标题

- 目的：
- 读者问题：
- 核心观点：
- 证据：F03, Q02, C01
- 例子/场景：
- 转场：
- 字数预算：
- 完成标准：
- 风险：NEEDS_SOURCE / NONE
```

## 结构检查

- [ ] 每个章节都服务于中心承诺，没有“为了完整而完整”的段落。
- [ ] 每个关键观点都关联素材证据或明确标注待补证据。
- [ ] 开头快速建立问题与收益，正文逐步兑现，结尾给出下一步。
- [ ] 结构深度不超过 3 层，章节数量与目标篇幅匹配。
- [ ] 标题不夸大正文不能证明的结果。
