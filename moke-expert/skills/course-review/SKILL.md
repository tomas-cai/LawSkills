# 课程评审 Skill

## 核心理念

审阅不是"找错"，是**在交付前做一次系统性检查**——识别结构性缺口、跨阶段断裂、内容深度不足和可教性风险。

## 输入

用户提供**课程项目目录的路径**。评审程序扫描目录下所有产出物文件，不要求完整的 Phase 00→05 流程——有部分文件也能审。

## 工作流程

本 Skill 按以下 5 个维度依次执行。每个维度独立评估，不依赖前一个维度的结论。

### 维度 1：结构完整性

检查产出物流是否完整，每个阶段预期产出物是否存在。

**操作**：扫描课程项目目录，对照以下标准检查：

| 产出一览 | 说明 |
|:---|:---|
| `00-*.md` | Phase 00（探索阶段）产出，如存在则评估其内容 |
| `01-*.md` | Phase 01 产出：需求来源、痛点验证、学习者画像、能力差距 |
| `02-*.md` | Phase 02 产出：学习目标、情绪曲线、对齐矩阵 |
| `03-*/` | Phase 03 产出：`00` 大纲 / `01` 学员手册 / `02` 讲师手册 / `03` 实操案例（含终端形态+技术栈+AGENTS.md 示例）/ `04` 测评方案 / `05` 课程课件 / `06` 课程详细大纲 |
| `04-*.md` | Phase 04 产出：前置测评、随堂验证设计 |
| `05-*.md` | Phase 05 产出：柯氏评估、迭代计划 |

**每一份产出物都应包含"本阶段完成检查"清单**——检查项应为已勾选状态（[x]），未勾选的需在评审中标明。

> 详细检查项见 `references/review-methodology.md` → 结构完整性

**格式一致性（跨文档格式变更审计）**：
当课程交付格式发生变更时（如 2 天→2 周），本检查确认所有文档统一使用新格式的术语。
详见 `references/review-methodology.md` → 维度 6：格式一致性


### 维度 2：内部一致性

验证跨阶段的信息是否一致——这是传统质检清单最常遗漏的维度。

**操作**：挑三个关键字段，沿产出物链追踪比对：

| 检查项 | 追踪路径 | 典型断裂 |
|:---|:---|:---|
| **目标人群** | Phase 01 画像 → Phase 02 目标难度 → Phase 03 案例场景 → Phase 04 测评 | 画像写"零基础毕业生"，案例却假设 2 年经验 |
| **核心痛点** | Phase 00/01 痛点 → Phase 02 惊叫点设计 → Phase 03 讲师话术 → Phase 05 复盘 | 讲师手册没有针对焦虑设计话术 |
| **学习目标** | Phase 02 目标清单 → Phase 03 测评方案 → Phase 05 达成度 | OBJ 在 Phase 02 定义了，Phase 03 没有对应测评 |

**方法**：从 Phase 01 开始，沿产出物流往下看，每到一个文件确认"这个文件里的信息是否还认同上一个文件里的同一个字段"。

> 详细检查项见 `references/review-methodology.md` → 内部一致性

**变更冲突检查**：当提议新增模块/环节/主题时，检查是否与已有内容冲突。
详见 `references/review-methodology.md` → 维度 8：变更冲突检查


**Phase 03 三角对齐**：检查大纲 ⇄ 学员手册 ⇄ 讲师手册三个文件对每个课时的描述是否一致。
详见 `references/review-methodology.md` → 维度 7：Phase 03 全域三角对齐（五文件互锁）


### 维度 3：内容深度

比 "文件存在" 更进一步——内容是否达到了 **可教学** 的质量。

| 深度层级 | 定义 | 判断方法 |
|:---|:---|:---|
| **L1 骨架级** | 有文件、有结构、有占位符 | 文件能打开，结构完整 |
| **L2 填充级** | 内容完整，可读性强 | 逐段阅读，没有"待填写"标记 |
| **L3 教学级** | 拿到就能上课，讲师不需额外准备 | 模拟一节课——只看手册，能讲吗？ |
| **L4 精品级** | 有视觉设计、有录屏、有课后扩展 | 学员体验完整，超出预期 |

**课程交付时应至少达到 L2**，关键模块（如 Day 1 的 M1）应达到 L3。

> 详细检查项见 `references/review-methodology.md` → 内容深度

**实操案例质量新增检查**：
每个案例是否标注了终端形态（Mobile APP / PC Web）？是否给出了推荐技术栈和选择理由？构建型案例是否有 AGENTS.md 配置示例？详见 `references/review-methodology.md` → 维度 3 → 实操案例质量检查。


### 维度 4：可教性

模拟"明天就要上课"场景，验证材料是否可执行。

| 检查项 | 操作方式 |
|:---|:---|
| **时间表可执行** | 把课程大纲的每段时间加起来，检查是否等于总时长 |
| **讲师能照着讲** | 打开讲师手册，从 M1 到结束逐段读——"这里有盲区吗？" |
| **案例可操作** | 还原案例场景——决策点有明确选项吗？参考答案有层次差异吗？ |
| **测评可评分** | 拿 3 份不同水平作业试评——评分标准能区分优/中/差吗？ |
| **技术依赖确认** | 实操环节用到的工具/平台/API 是否都已确认可运行？ |
| **技术栈合理性** **[A]** | 推荐技术栈是否匹配终端形态？是否提供了多框架备选方案？AGENTS.md 配置示例是否完整？（**B/C 类**改用 `review-methodology.md` 的等价判据 / 标 N/A） |


### 维度 5：风险评估

识别课程交付前最可能出问题的 3 件事：

```
风险 1：[如"M4 自由手搓依赖 AI 工具可用性"]
  影响：工具不可用 → 整个 M4 叙事弧断裂
  概率：低
  应对：备本地演示录像降级

风险 2：[描述]
  影响：...
  概率：...
  应对：...

风险 3：[描述]
  影响：...
  概率：...
  应对：...
```

**风险来源**：讲师经验（没讲过的环节）、技术依赖（AI 工具、API）、学员差异（跨度大的分层）、内容时效性（过时的案例）。

## 产出

## 扩展检查（维度 6-10；6-8 按需启用，维度 9 条件必做，维度 10 M/L 档必做）

主流程的 5 个维度是**每次评审必做项**；以下 5 项按触发条件追加（维度 10 对 M/L 档为必做），详细清单见 `references/review-methodology.md`：

| 扩展维度 | 何时启用 | 检查要点 |
|:---|:---|:---|
| 维度 6 格式一致性 | 课程交付格式发生变更（2 天→2 周、线下→线上、讲座→翻转） | 所有文档的时长、形式、术语是否统一为新格式 |
| 维度 7 Phase 03 三角对齐 | 已产出 `03-教学材料包/` | 大纲 ⇄ 学员手册 ⇄ 讲师手册 ⇄ 实操案例 ⇄ 测评方案五文件互锁 |
| 维度 8 变更冲突检查 | 新增模块 / 环节 / 主题时 | 与已有内容是否冲突、是否需同步更新关联文件与 Changelog |
| **维度 9 学习体验落地（LXD）** | **已产出 `03-教学材料包/`（含课件或 `06-课程详细大纲`）→ 此时为必做项** | **见下表；专查「设计层写了、课堂层没落」的断点** |
| **维度 10 角色 × 层级结构评审（v1.6）** | **M / L 档必做**（≥2 天，或含实战 / 客户现场 / 答辩）；S 档精简 | 按四角色分别给分；专查「规范写了、评审查不出」与「谁在做、按哪层判据、有无越界」 |

### 维度 9：学习体验落地（v1.1 新增）

> 结构、对齐、深度、可教性都过关，仍可能出现「开场页剧透惊叫点 / 一页塞满 / 爽点只写在表格里没有课堂动作」。本维度专门验收**体验层是否从设计视图编译成了课时动作**。

| 检查项 | 判据 | 典型不合格 |
|:---|:---|:---|
| **惊叫点未被剧透** | 开场页 / 学员可见页不得出现顿悟点、惊叫点编号与位置 | 课程全景页标注「顿悟 1→2→3」 |
| **视图分离** | 情绪曲线属设计视图，只在 `02` 与讲师手册附录；学员页只有阶段、产出物、进度 | 把 `02` 的负荷曲线直接做成课件页 |
| **单页负荷** | 一页一个要点、超过 30 字换图或清单 | 开场 5 分钟塞入 12 时点 + 6 课次 + 周期账 |
| **课时节拍** | 每 15-20 分钟 1 张切换页；每 45 分钟留 5 分钟消化；高负荷后有缓冲 | 全程讲授无切换 |
| **爽点是动作不是标签** | 提示卡、即时反馈、进度感知、去羞耻化话术须能在讲师手册/课件里指到具体位置 | 检查表写「爽点：给进度预期」，但无对应页 |
| **体验层按课时落地** | `course-polish` 已调用并产出 `02-讲师手册·润色版.md`（或用户明确确认不需要） | 只有 `02` 的情绪曲线，无任何按课时润色 |
| **惊叫点命中已验证** | P2/P3 或首期反馈中有命中率数据；未验证须列为风险 | 设计文档自称有 3 个惊叫点，零验证数据 |
| **第 10 类 · 工具卡闭环（v1.5 新增）** | 数量宣称可数（宣称 N = 编号数）/ 发放动作齐全（`02` 发卡清单 = `01` 组件清单）/ 示范按卡走 / 对手戏覆盖（`03` 角色卡对每个问题有答法）/ 落点实物存在 / 引用落点可达。详见 `course-review/references/review-methodology.md` 9.8 | 课件宣称「七问」而上屏是分号串；「带四样东西」只发两件；讲师兜底说「附录有卡」而附录无此卡 |
| **第 9 类 · 口径一致性（v1.4 新增）** | 术语 L1 逐字一致 / L2 白话有绑定句 / L3 同页不混用；页内 `steps` 合计 = 页 minutes；分块对齐 `02-讲师手册` 分钟轴；成功标准覆盖面 ≤ 活动实际角色数；同课次只 1 个可授课载体（`00-课件状态说明.md` 齐全）。详见 `course-review/references/review-methodology.md` 9.7 | 课件写「三层角色」而真源是「三类角色」；实操页步骤合计 60 min 而本页 27 min；3 轮只排 2 类角色却要求三类全覆盖；旧 PPTX 与 HTML 并存且旧角色轴仍可上课 |
| **第 8 类 · 双视角完整性（v1.3 新增）** | 每页同时具备「学员可读正文」与「逐页讲解层」；上屏标题按 `course-design/references/phase-03-development.md` →「学员视角标题契约」4 条合格；核心示例完整上屏；⛔ **验收不得只跑负向词表**，须另跑 `common-tools.md` →「正向内容验收」7 项结构判据 | 0 禁词 + 布局全通过，但上屏是设计目标语 / 半截句 / 索引卡标题；讲师视图只有元数据；「三句改写」页一句改写都没有 |

> 启用扩展检查时，在评审报告「各维度发现」后追加维度 6 / 7 / 8 / **9 / 10** 的结论，并把问题并入待办清单。维度 9 写进 `体验落地: /5`，维度 10 须写进四层独立评分。
> **维度 9 取证方式（v1.2 新增）**：按 `course-design/references/common-tools.md` →「规范变更后的全包回归检索」执行（10 词表 + 5 类范围 + 三类判定 + 验收记录）；**专家包规范修订或评审整改后须重新取证**，不得沿用整改前的检索结论。
> **⛔ v1.3 取证硬约束**：词表只查「不该出现的词」，查不出「本该有却没写」。故维度 9 结论必须同时包含**负向检索结果**与**正向内容验收 7 项分布**；缺正向分布即判「取证不完整」，不得给出 `体验落地` 评分。**`0 禁词 + 100% 布局通过 ≠ 内容可用`**。
> **⛔ v1.4 取证硬约束**：第 9 类须附**术语矩阵**（文件 × 术语 × 次数，含 pptx 解压后 XML）与**时长表**（页 × 步骤合计 × 页 minutes × 讲师手册段），并写明**载体清点结果**（可授课载体数 / 旧载体残留数 / 是否标 ⛔）。⛔ 不得以「已检查，一致」代替计数；**`术语 0 残留 ≠ 内容可用`**（旧代产物即使 0 残留也不能上课）。
> **⛔ v1.5 取证硬约束**：第 10 类须附**五点清点矩阵**（卡 × 定义 / 发放 / 上屏可数 / 对手戏 / 实物）与**悬空引用清单**（含讲师兜底语逐条验证结果）。悬空落点 → P0（课堂当场翻车）；**`工具卡齐全 ≠ 学员会用`**。

### 维度 10：角色 × 层级结构评审（v1.6 新增 · M/L 档必做）

> 维度 1-9 查「内容对不对、上屏全不全」；本维度查「**谁在做、按哪层判据、有没有越界**」。规范层 1.6~1.9 新增的阶段归属 / 结构模式 / 层级契约 / 四角色模型，整改前在评审侧 **16 个概念全部 0 命中**（G-21，见 `references/role-based-review.md` §4）。

**评审前先换帽**（不写即维度 10 记 0 分）：

```
【评审换帽】本轮按四角色分别评审，判据不互相顶替。规模档：S / M / L。启用卡：A / B / C / D。
```
