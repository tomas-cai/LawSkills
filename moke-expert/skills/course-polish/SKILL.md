# 课程润色 Skill

## 核心理念

**同一句话，换种说法，冲击力完全不同。** 课程润色不做内容层面的调整（不改教学目标、不删知识点），只做**体验层面的优化**。

如同电影剪辑——剧本不改，但剪辑节奏、配乐、镜头语言决定了观众是否入戏。

> 路由位置：在 `course-design` 完成 Phase 03（`03-教学材料包/`）之后、交付前 `course-review` 之前使用。输入以 `03-教学材料包/` 下的 `00`/`02`/`05` 为准。
> **v1.1 起，本技能的调用已列为 `course-design` Phase 03 完成条件之一**：仅有 `02-课程设计方案.md` 的情绪曲线与逐模块三点检查表，不视为体验层完成；须由本技能按课时编译成话术、节奏、互动与爽点动作，产出 `02-讲师手册·润色版.md`（或由用户明确确认不需要润色）。

## 工作流程

本 Skill 按以下 5 个维度依次对讲师手册进行润色。每个维度独立操作，不依赖前一个维度的结论。

### 维度 1：叙事弧润色（Story Arc）

每个课时应该有一条微型的"起承转合"线。检查讲师手册中每个课时的结构：

| 阶段 | 时长占比 | 作用 | 缺失表现 |
|:---|:---:|:---|:---|
| **起**（钩子） | ~10% | 扔一个问题/一个案例，让学员产生"为什么？" | 直接进入主题，没有引发好奇 |
| **承**（铺陈） | ~40% | 建立认知框架，给出方法论 | 信息点平铺，没有主次 |
| **转**（高潮） | ~20% | ⭐ 制造一个"原来如此"时刻 | 全程没有起伏，学完就忘 |
| **合**（收束） | ~30% | 联系实际 + 布置作业 | 截然而止，没有升华 |

> 详见 `references/polish-methodology.md` → 叙事弧润色

### 维度 2：话术润色（Script Polish）

把平铺直叙的讲师话术改写成更有画面感、更容易记住的表达。

| 原话 | 润色后 |
|:---|:---|
| "AGENTS.md 是把你的项目规则告诉 AI" | "想象一下，你给 AI 画了一条跑道。你不是在跟它聊天，是在给它发一本操作手册。这本手册就叫 AGENTS.md。" |
| "自由手搓的目的是让你体验没有规范时的状态" | "先让你自己摔一跤——摔了才知道痛在哪。然后我们再教你走路。" |

**润色原则**：
1. **画面感**——不要说概念，说画面（"发一本操作手册"比"告诉规则"有画面）
2. **对比**——好的表达建立在对比之上（"摔跤 vs 走路"）
3. **悬念**——先扔问题，再给答案（"你知道吗？"）
4. **短句**——一句话不要超过 25 个字

> 详见 `references/polish-methodology.md` → 话术润色

### 维度 3：节奏设计（Energy Rhythm）

同一个讲师手册，早上讲和下午讲、课前讲和课后讲，效果完全不同。节奏润色根据**该课时的当天时间 + 学员精力状态**调整：

| 时段 | 学员状态 | 设计策略 |
|:---|:---|:---|
| 09:00-09:30 | 清醒但未进入状态 | **用问题开场**，不用"大家好今天我们来学…" |
| 09:30-11:00 | 专注力高峰 | **核心内容**安排在此 |
| 11:00-12:00 | 开始疲劳（血糖下降） | **互动环节**替代讲授 |
| 13:30-14:30 | 午饭后昏沉 | **动手实操**替代听讲（坐着不动更困） |
| 14:30-16:00 | 回升 | **轻量内容 + 讨论** |
| 16:00-18:00 | 疲劳高峰 | **收尾 + 明天预告**，不要安排新内容 |

> 详见 `references/polish-methodology.md` → 节奏设计

### 维度 4：互动设计（Engagement Design）

不是"有没有互动"的问题，是"学员想不想参与"的问题。

| 互动类型 | 适用场景 | 设计要点 |
|:---|:---|:---|
| **冷call** | 检验理解 | 不要叫"那个穿蓝衣服的同学"——提前说"我待会会问一个问题，随机叫一位同学" |
| **同桌讨论** | 引出观点 | 给明确问题 + 30s 计时，不要"大家讨论一下"（太宽泛） |
| **举手投票** | 快速摸底 | "觉得 A 方案更好的举手——觉得 B 更好的举手"——比"大家觉得怎么样"有效 |
| **快速写作** | 巩固记忆 | "用一句话总结刚才我讲的三个区别，30 秒——开始"——不要只让学生"想" |
| **错误展示** | 制造惊叫点 | 展示一个真实的错误范例，让其他学员发现"问题在哪"——比自己讲解效果好 10 倍 |

> 详见 `references/polish-methodology.md` → 互动设计

### 维度 5：临场应变（Live Contingency）

给讲师手册补充"如果…怎么办"的应急标注：

| 场景 | 应对 |
|:---|:---|
| **时间不够** | 标出可以砍掉的部分（"此段跳过不影响主线"） |
| **时间过剩** | 标出可以展开的讨论题（"如果时间充裕，可以加这个案例"） |
| **冷场** | 自问自答脚本："我在准备时也想过这个问题…你们有没有类似的？" |
| **学员偏离话题** | "好问题，把它记下来我们课后聊——现在先回到主线" |
| **技术故障** | "我们先用录播演示代替" |

> 详见 `references/polish-methodology.md` → 临场应变

## 润色粒度：按课时

当一个课程有多个独立课时时，润色不是对整个讲师手册一次性做完的——是**逐个课时**做的。

每润色一个课时，输入该课时的三份材料：

| 输入材料（均位于 `03-教学材料包/`） | 提供什么 | 润色维度 |
|:---|:---|:---|
| `02-讲师手册.md` 中该课时的章节 | 讲师话术、时间分配、互动环节 | 维度 2 话术 + 维度 3 节奏 + 维度 4 互动 |
| `00-课程大纲.md` 中该课时的描述 | 主题名、时长、核心活动 | 维度 1 叙事弧（起承转合是否完整） |
| `05-课程课件/课X-主题.pptx` | 每页画面的叙事逻辑 | 维度 1 视觉叙事 + 维度 5 临场标注 |
| **最终页锚映射表**（v1.3 新增） | 课件最终页序 ↔ 润色版 / 讲师手册页序的对应关系 | 维度 2 话术与维度 5 临场标注的**页锚重算**；无此表不得回灌 |


> 目录编号以 `course-design` 技能的「产出物契约」为准：`00` 大纲 / `01` 学员手册 / `02` 讲师手册 / `03` 实操案例 / `04` 测评方案 / `05` 课件 / `06` 详细大纲。

润色逻辑：大纲定"结构有没有断"，讲稿定"话术有没有力"，PPT 定"画面跟不跟得上声音"。

### 润色成果回灌契约（v1.3 新增）

> 缺陷 **G-4**：润色版课1 章已有 5 条逐字话术 / 4 互动 / 4 应急且全部带页锚，但课件里一句都没有；「讲师视图」被做成 6 个元数据字段。更严重的是**润色版用 18 页体系、课件是插入 2A 后的 19 页体系**，页锚已错位且未重算，即便回灌也会指错页。

1. **页锚优先**：回灌前先产出「最终页锚映射表」（课件页序 ↔ 润色版 / 讲师手册页序）；⛔ 页序体系不一致时禁止直接按原页码挂话术。
2. **回灌到讲解层**：五维润色成果中属于「讲师讲什么」的部分（逐字话术、提问追问、互动指令、应急口径），须写进课件**逐页配套的讲解层**（PPT 备注 / HTML 讲师视图 / 逐页讲解卡），使讲师打开任一页即可开讲。
3. **上屏 / 不上屏分流**：回灌内容一律**不上屏**；学员侧文案仍以 `01-学员手册.md` 与「逐页双视角文案表」为准，润色**不改变教学内容**。
4. **代理关系不得永久挂账**：若在课件尚未生成时以 `06` 蓝图代理润色，须在润色版 0.1 适配声明标注「**页锚为代理值，课件定稿后待回补**」，并列入 Phase 03 完成条件；课件一旦产出，须按本契约重算并回灌，⛔ 不得把「当时未生成」当作永久豁免。
5. **自检**：回灌后逐课时核对「有讲解层的页数 / 课件页数 = 100%」，并把结论写进润色自检表（作用域 = `本课时 + 课件`）。
6. **术语服从单一真源（v1.4 新增）**：润色只能改「怎么讲」，⛔ 不得改组件名、表头、验收口径、物件名 —— 这些以 `01-学员手册.md` 组件表 / `01` 验收线 / `04-测评方案.md` 观察表为唯一来源。允许把术语讲成白话（如「可验证事实」→「能核对的事实」），但**须在同一页或相邻页保留绑定句**，否则按不通过处理（`phase-03-development.md` →「术语与口径一致性契约」L2）。
7. **页时长不得被润色改动（v1.4 新增）**：润色若调整节奏（如把示范压到 12 分钟），须同步 `02-讲师手册.md` 时间轴与课件页级 minutes，并重跑「口径三向核对」；⛔ 只改话术不改时间轴，会造成步骤合计与页时长不符（G-7）。
8. **兜底语落点必须真实存在（v1.5 新增）**：润色新增或改写的应急话术（fallback）凡指向「手册 / 附录 / 案例里有 ××」，须先检索验证目标文件确有该内容——悬空落点判 P0（G-12）；同时 ⛔ 不得把上屏编号列表压成分号串，口播可省字、编号结构不可省（G-10）。

## 产出

完成润色后，输出两份文件：

1. **`03-教学材料包/02-讲师手册·润色版.md`**（全课时合集）——在原讲师手册基础上用标记增补
2. **`03-教学材料包/05-课程课件/课X-主题-讲课版.html` 的讲师视图**（默认载体，v1.4）——回灌进 `?t=1` 讲师视图；仅当用户明确要求 PPTX 时才出 `课X-主题·润色版.pptx`（可选标注节奏点与互动时机）

润色版不替代原版：

```
🔥 叙事弧改进建议
✨ 话术润色版本
⏱ 节奏调整建议
🎯 互动环节设计
🚨 应急标注
```

原版讲师手册保持不变，润色版作为增补参考。

## 润色自检模板（v1.2 新增）

> 缺陷 **G-3**：第一次实战的润色版把「本文件未新增学员可见页」写成「惊叫点信息只在本讲师用文件」——把局部自检当成了全包结论；实际 `00-课程大纲.md` / `01-学员手册.md` / `06-课程详细大纲/` 均保留设计侧惊叫点信息。第二次实战中课程侧已把它改为「本文件作用域声明」，本模板把该约束固化到技能层。

### 三条硬约束

1. **作用域声明必填**：每条自检结论须注明作用域 —— `本课时` / `本文件（润色版）` / `全包`。**默认只代表本文件**，不得外推。
2. **全包结论只能引用**：涉及「全包是否有剧透 / 视图分离是否合规」时，必须引用 `course-review` 维度 9 的全包回归检索结论（词表与范围见 `course-design/references/common-tools.md` →「规范变更后的全包回归检索」）；若评审尚未执行，写「**全包检索尚未执行，本项不作结论**」，不得自行推断。
3. **禁止句式**：「惊叫点信息只在本文件」「全包无剧透」「所有材料均无…」「其余 N 章未变」等**无限定语的全局断言**。改写示例：「本润色版未新增学员可见页；全包视图分离结论见 `课程质量评审报告.md` 维度 9」。

### 自检表模板（放进 `02-讲师手册·润色版.md` 末尾）

| 检查项 | 作用域 | 本轮结论 | 全包结论来源 |
|:---|:---:|:---|:---|
| 未新增学员可见页 | 本文件 | … | — |
| 惊叫点编号 / 触发词仅讲师可见 | 本文件 | … | — |
| 五维度按课时覆盖（叙事弧 / 话术 / 节奏 / 互动 / 应急） | 本文件 | … | — |
| 原版讲师手册未被覆盖、仍为增补参考 | 本文件 | … | — |
| **视图分离合规 / 惊叫点未剧透** | **全包** | ⛔ **不得由本文件单独判定** | `course-review` 维度 9 全包检索结论，或「尚未执行」 |
| **逐页讲解文案已按最终页锚回灌课件 / 代理关系已标「待回补」（v1.3）** | 本课时 + 课件 | … | 最终页锚映射表；未回灌须写明「待回补」及计划 |


> 「作用域」列不得留空；「全包结论来源」为 `—` 的行，结论不得外推到其他文件。
> **被整改的课程材料升版时须同步本文件的状态引用**（如「原版讲师手册未改动」在被同步后即失效），并按 G-1 全包回归规则复验；本技能本身不改变任何教学内容。
