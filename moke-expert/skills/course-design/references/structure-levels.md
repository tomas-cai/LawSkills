# 结构层级与术语契约（L0-L6）

> 版本：1.8.0 新增。回答一个问题：**我们说的「结构」，到底是哪一层的结构？**
> 起因：用户质疑「叫课程结构，是不是像一节课的结构？该叫培训项目课程体系吗？」——这个语感是对的，暴露了专家包 1.7.0 把**项目级方法**与**课程级方法**装进同一个文件、共用「结构」一个词的问题（缺陷 **G-18 层级混装**）。

---

## 0. 一句话

**「课程结构」不是不用，而是只能指一门课内部。多天培养项目的结构，叫「项目架构（Program Architecture）」。**

> 「培训项目课程体系」不是一个合法术语：**项目**是有起止的干预，**体系**是无起止的课程地图，两者不在同一层，行业里没有这个说法。

---

## 1. 七层概念表（中文规范叫法 / 英文 / 核心问题 / 方法论 / 产出物）

| 层 | 中文规范叫法 | 英文 | 核心问题 | 主方法论 | 典型产出物 |
|:---:|:---|:---|:---|:---|:---|
| **L0** | 培训体系 | Training System | 组织的能力缺口靠什么长期补？ | 能力模型、岗位分析、HPT、70-20-10 | 制度 / 师资 / 资源规划 |
| **L1** | **课程体系**（学习路径） | Curriculum / Learning Path | 这类人从入门到胜任要走哪几门课？ | 课程地图（curriculum mapping）：任务 → 能力 → 课程 → 学时 → 认证 | 课程地图、进阶路径、认证阶梯 |
| **L2** | **培训项目**（学习项目） | Learning Program | 这一次干预怎么产生业务结果？ | **6Ds 六法则**、ADDIE 整体环、Brinkerhoff、Kirkpatrick L1-L4 | 项目方案、转化设计、评估方案 |
| **L3** | **课程** | Course | 一个能力块怎么教到位？ | **逆向设计**（出口→证据→活动）、**4C/ID**（复杂技能）、Merrill 五原理 | 课程大纲、模块划分、考核标准 |
| **L4** | **课次** | Session | 这一次课（2h / 半天 / 1 天）怎么排？ | 4C/ID 任务序列、认知负荷分配（CLT） | 分钟轴、时间分配表 |
| **L5** | **课堂 / 教学活动** | Lesson / Activity | 这 15-45 分钟怎么发生？ | **Gagné 九事件**、Merrill 五原理、练习与反馈设计 | 脚本、话术、工具卡 |
| **L6** | **载体** | Delivery Asset | 怎么呈现、怎么带走？ | 双视角契约、视觉与可读性 | HTML / PPT / 手册 |

**层级越高越"决策"，越低越"执行"**。上一层锁定出口与约束，下一层才有意义；反过来（先排课时再想出口）必错。

## 2. 判定口诀（30 秒定位）

| 你正在纠结的问题 | 层级 |
|:---|:---:|
| 这类人要不要学这个、学几门、先学哪门 | **L1** |
| 这 5 天怎么排、实战占几天、客户哪天到场、谁验收 | **L2** |
| 这门课分几个模块、每个模块什么目标、怎么考 | **L3** |
| 这一天 270 分钟怎么分块、每块多少分钟 | **L4** |
| 这 90 分钟讲师说什么、学员做什么 | **L5** |
| 这一页上写什么字 | **L6** |

> ⛔ **跨两层同时决策 = 返工**。先答上表，再动笔。

## 3. 常见混用与修正

| # | 混用 | 症状 | 正确做法 |
|:---:|:---|:---|:---|
| M-1 | 把 L2 称「课程」 | 客户以为买的是课时；报价按天算，交付按结果算 | 对外称「**培养项目 / 训练营**」；对内称「**项目架构**」；课时只是它的一个维度 |
| M-2 | 把 L1 称「体系」但只有一门课 | 一进门课就敢叫「XX 课程体系」 | 单门 → 课程；≥3 门且有进阶关系 → 才叫体系 |
| M-3 | **用 L3 方法做 L2 设计** | 拿「课程阶段」直接填「项目天数」→ 天数用完了内容还没完（**G-16** 的真实成因） | L2 先用 6Ds 定完整体验（课前/课中/课后/实战/评估），再把课程当其中一种活动放进去 |
| M-4 | 用 L2 语言做 L4 排课 | 只有「阶段」没有分钟轴、没有负荷曲线 | L4 必须落到分钟轴 + 认知负荷 |
| M-5 | 「培训项目课程体系」 | 项目（有起止）与体系（长期地图）硬拼 | 二选一，不要造词 |
| M-6 | 一个文件里混装两层方法 | 同一份文档里 6Ds 与 Gagné 并列、4C/ID 与课程地图并列 | 标题必须带层级标签；一章内不得混两层 |

## 4. 本项目（AI 落地端到端实战）的层级映射

| 层 | 本项目对应物 | 说明 |
|:---:|:---|:---|
| L1 课程体系 | **暂不存在**（单项目） | 若做「FDE 初 / 中 / 高 + 认证 + 复训」才升级为体系 |
| **L2 培训项目** | **「AI 落地端到端实战」5 天培养项目**（1350 min / 30 课时） | 含课前预习、5 天集中、课后回炉、通关评审、补交窗口 |
| **L3 课程** | **课1 场景梳理 / 课2 方案设计 / 课3 智能体实施** | 三门课，各 270 min，各有独立出口与评议 |
| L4 课次 | 每天的上下午分块（M0-M11 各自的时间轴） | 270 min 内的段落与分钟轴 |
| L5 课堂 | 每个模块内的示范 / 跟做 / 评议 / 工具卡发放 | 分钟级教学事件 |
| L6 载体 | 3 份 HTML 讲课版 + 学员手册 + 讲师手册 | 学员版 / 讲师版 |

**关键结论**：本项目是「**1 个 L2 项目，内含 3 门 L3 课程 + 2 天 L2 级实战**」。
实战日（D4/D5）**不是第 4、第 5 门课**，而是项目级的转化活动（6Ds 的 D3「引导学以致用」+ D4「推动学习转化」）。这一点若不说清，就会反复出现「后两天不知道放什么课」的问题——因为 L2 的活动本就不只有「上课」。

## 5. 对外 / 对内 / 学术 三套说法（都合法，别混场合）

| 场合 | 用词 | 理由 |
|:---|:---|:---|
| 对客户 / 销售 | 训练营、培养项目、5 天实战营 | 卖结果，不卖课时 |
| 对教研 / 内部设计 | 项目架构、课程结构、课次时间轴 | 层级别混淆才可分工 |
| 学术 / 评审材料 | curriculum / program / course / session / lesson | 与国际文献对得上，便于引用 |

---

## 6. 硬规则（与 SKILL 第 9 条对应）

1. 结构类文档的**标题必须带层级标签**：`[L2 项目]` / `[L3 课程]` / `[L4 课次]`。
2. 文件名可历史延续（避免断链），但**正文首行必须声明层级**。
3. **一章之内不得混用两个层级的方法**（例：6Ds 不与 Gagné 同节）。
4. 出现「课程体系」字样前，先回答：**有没有 ≥3 门课且有进阶关系**？没有 → 写「课程」。
5. ⛔ 禁止造「培训项目课程体系」这类跨层词。
