# 大型培养项目结构设计（L2 项目架构 · 含课程与课次下的落地）

> **层级声明（v1.8 补）**：本文件主战场是 **L2 培训项目**（多天 / 多阶段 / 含实战），其中 §3 五模式与 §4 选择矩阵同时适用于 L2 与 L3；§2 三张前置卡属 L2；§7 回接属 L3/L4 的课程内技术。**层级定义与方法论分工见 `structure-levels.md`，⛔ 不得混用两层方法。**
> 适用：≥2 天、或 ≥3 个阶段、或含「真实项目 / 客户现场 / 结业答辩」的培训项目。
> 不适用：单次 90 min 以内的单点技能课（走 `phase-02-design.md` 的模块设计即可）。
> 版本：1.7.0 新增，1.8.0 补层级声明。闭合缺陷 **G-16 / G-17 / G-18**，配套边界 **V-6**。

## 0. 一句话立论

**顶级做法不是「设计课程结构」，而是「设计一条从当前绩效到目标绩效的路径」，结构是这条路径的推导结果。**

所以顺序永远是：**绩效 → 任务 → 结构 → 时间 → 载体**。凡是从「我们有 5 天，怎么排」开始的，结构必错。

⛔ 三条同样的错路：
1. **主题清单式**：把知识点列成表，按「基础 / 进阶 / 实战」分三段装载。→ 学员知道很多，做不出一件完整的事。
2. **教学法套路式**：套「先讲完方法、最后做全案」。→ 全案要等到最后一天，前面全是隔离练习，迁移率极低。
3. **算术均分式**：每段等分钟。→ 该吃重的段吃不重（本项目 G-15 实例：三段各 270，让「实施」只占 33%）。

## 1. 理论栈：六道闸

每一道闸回答一个问题。**跳闸的方式不是「想不到」，而是「上一道闸的答案没写下来就进下一道」**。

| # | 闸 | 回答什么问题 | 代表模型 / 出处 | 跳过的后果 |
|:---:|:---|:---|:---|:---|
| 1 | **绩效诊断** | 这是不是培训能解决的问题？ | 绩效分析（Mager & Pipe《Analyzing Performance Problems》）；HPT / ISPI | 用培训去治「没工具、没权限、没激励」的病 |
| 2 | **出口绩效** | 结业那天，他必须能**独立**做出什么？谁验收？ | 逆向设计（Wiggins & McTighe《Understanding by Design》）；可委托专业活动 EPA（ten Cate） | 目标写成「了解 / 掌握」，无法判定，后面全是空转 |
| 3 | **任务分解** | 这件事由哪些任务构成？各多常见、多关键、多难？ | DACUM 职能分析；认知任务分析 CTA（专家解题过程） | 模块边界凭感觉切；漏掉低频高风险的致命任务 |
| 4 | **任务类别与支架** | 用几个「整体任务」承载？难度怎么阶梯？支架怎么递减？ | **4C/ID**（van Merriënboer & Kirschner《Ten Steps to Complex Learning》第 4 版 2024） | 切成一堆 part-task，学员没见过全貌；或全程强支架，独立做不出来 |
| 5 | **完整体验与转化** | 课前 / 课中 / 课后各承担什么？谁推动落地？ | **6Ds**（Wick / Pollock / Jefferson）：D1 界定业务结果 → D2 设计完整体验 → D3 引导学以致用 → D4 推动学习转化 → D5 实施绩效支持 → D6 总结效果 | 课上很热、三周归零（迁移失败是默认结局，不是意外） |
| 6 | **评估与认证** | 什么证据算过关？分级标准是什么？ | 真实性表现评估 / 量规；掌握学习（Bloom）；Kirkpatrick L1-L4；Brinkerhoff 成功案例法 | 考记忆不考表现；「通关」和「能用」不是一回事 |

### 4C/ID 的四件套（结构设计的主发动机）

| 组件 | 是什么 | 排期含义 |
|:---|:---|:---|
| **学习任务** | 真实、完整、整体的任务（case / project / problem），集成知识+技能+态度 | 每个单元必须有一次**做完整件事**，不是做其中一段 |
| **支持性信息** | 解释「这类问题怎么想」——非例行判断、心智模型、认知策略 | 讲在最需要它的任务**之前或之中**，且对该任务类别**始终可查** |
| **程序性信息** | 「这一步怎么做」的 if-then 规则、清单、操作卡 | **即时给（just-in-time）**，随熟练度**快速撤除** |
| **部分任务练习** | 只针对必须自动化的**例行动作**做大量重复 | ⛔ 只对「例行」用；**复杂判断不可拆成 part-task 练** |

**锯齿形序列（sawtooth）**：进入新任务类别时给强支架 → 同类任务内逐步撤除 → 独立达标 → 进入更难类别、支架重新给满。这是「难度阶梯 + 支架递减」的双螺旋，不是「先易后难」四个字。

**效果量**：Costa / Miranda / Melo（2022）元分析汇总 d ≈ 0.79；2025 年系统综述子分析 g ≈ 0.76，异质性大。→ 可以说「有较强证据支持」，不可说「用了就提升 79%」。

## 2. 三张前置卡（缺一张，禁止宣称「最佳实践」）

**这是本文件最硬的规矩**：结构方案定稿前，三张卡必须落到文档里；任一张为空，方案只能标为「假设版结构」，并在首页写明缺什么、谁来补。

### 卡 1：出口绩效卡（Exit Performance）

```markdown
| 项 | 内容 |
|:---|:---|
| 结业时能独立完成的产出物 | （一件可交付物，不是一个知识点） |
| 在什么条件下完成 | 有/无客户在场？有/无模板？时间压力？数据是否干净？ |
| 达到什么标准算过关 | 可观测判据 ≥3 条，来自量规而非讲师印象 |
| 谁验收 | 客户 / 资深从业者 / 内部主管（不是讲师自己） |
| 独立度等级 | 观察 → 在监督下做 → 独立做 → 能教别人（EPA 四级） |
```

> EPA（Entrustable Professional Activity）的价值：它把「学会」换成「**可以被托付**」。医疗教育用它替代了上千条细碎目标——因为委托人只关心「这件事能不能交给他做」。

### 卡 2：任务清单卡（Task Inventory）

```markdown
| # | 任务 | 频率 | 关键性（错了多贵） | 难度 | 是否可培训 | 归属 |
|:---:|:---|:---:|:---:|:---:|:---:|:---|
| 1 | 客户访谈问出可验证事实 | 高 | 高 | 中 | 是 | 课堂主练 |
| 2 | 跨系统接口对接 | 低 | 高 | 高 | **否**（无权限/无接口） | 只做判据，不做实施 |
```

判据：**「可培训 = 是」且「频率×关键性」高的任务**才配占课堂分钟；其余转岗位手册、绩效支持、或明确「本课不教，只教如何识别与求助」。

### 卡 3：学员起点卡（Entry Level）

```markdown
| 项 | 内容 |
|:---|:---|
| 已具备 | （前测/访谈得出，不是假设「零基础」） |
| 常见错误概念 | ≥3 条（教学设计要正面撞这些错误概念） |
| 起点差异 | 同班最大差距在哪（决定是否需要分层任务） |
```

> 没有起点卡就会犯两个反向错误：把有经验的人当新手（触发**专长逆转效应**：给老手的强支架反而降低学习），或把新手当有经验的人（直接给完整任务却不给支架）。

## 3. 五种项目结构模式

先选模式，再排时间。**模式选错，分钟账再漂亮也是错的。**

| 模式 | 形态 | 最适合 | 时间账特征 | 典型失败信号 |
|:---|:---|:---|:---|:---|
| **P1 阶段块状** Phase-blocked | 第 1 段全讲 A 阶段、第 2 段全讲 B 阶段、最后 C 阶段 | ①各阶段**可独立成立**（做完 A 的产出物就能用）②学员已有阶段级经验、缺的是单段深化 | 每段一个或多个单元；段内 part-task 练习 | 学员到最后一个单元才第一次看到完整链路 |
| **P2 整体任务螺旋** Whole-task spiral | 每个单元都做一次「缩小版全流程」，难度与真实度逐轮上升 | 复杂综合能力、迁移要求高、学员是新手 | 锯齿形：同类任务内支架递减 | 单元太多导致每次全流程都太浅（走马灯） |
| **P3 案例阶梯** Case ladder | 同一动作、换越来越难的情境（干净 → 脏 → 真） | **单一**复杂技能（如访谈、诊断、谈判） | 任务类别 = 案例难度 | 只练一个动作，学员缺全局观 |
| **P4 项目主线** Project-based | 一条真实项目贯穿全程，每个单元推进项目一段 | 有真实客户/真实交付物、周期允许间断 | 项目里程碑即单元边界 | 客户不配合 → 全线停摆；进度不可控 |
| **P5 混合旅程** Blended journey | 课前（知识+前测）→ 集中工作坊 → 在岗任务 → 间隔回炉 → 认证 | 大规模、时间贵、迁移要求最高 | 集中段只做「非讲不可的事」 | 只做集中段，前后不设计（6Ds D2/D4 缺失） |

### 混合与叠加

真实项目几乎都是**叠加**：`P5 旅程` 里装 `P1 或 P2 的集中段`，集中段内部可能用 `P3 阶梯`。**但一个单元只能标称一个主模式**，否则无法审计。

## 4. 结构模式选择矩阵

按顺序回答，第一个「是」即为推荐模式（顺序不能颠倒，前面的是硬约束）：

| 序 | 判别问题 | 是 → | 否 → |
|:---:|:---|:---|:---|
| Q1 | 学员起点差异极大（同班既有新手也有熟手）？ | 先分层，再选模式（否则一律 P2 会伤老手、P1 会伤新手） | 下一问 |
| Q2 | 出口绩效是**单一**复杂技能？ | **P3 案例阶梯** | 下一问 |
| Q3 | 各阶段产出物**彼此独立可用**（A 的产物不需要 B 才能生效）？ | **P1 阶段块状**（合法） | 下一问 |
| Q4 | 有真实客户/真实交付物且周期允许间断？ | **P4 项目主线**（可与 P2 叠加） | 下一问 |
| Q5 | 集中时间 ≤5 天、迁移要求高？ | **P2 整体任务螺旋**（默认答案） | **P5 混合旅程** |

> **默认判据**：如果答不出 Q3 的「是」，就不要用 P1。**「成果物强链式」是所有 P1 误用的根源**——正因为后一段依赖前一段，才更需要让学员尽早看到整条链，而不是更晚。

### P1 的合法用法（唯一一条）

P1 只在「**每段都能独立交付**」时成立。例如「Excel 基础 → 数据透视 → 图表呈现」：每段学完都能交一件东西。
反例（本项目 G-14）：画像表 → 机会 → 流程 → 范式卡 → 搭建 → 接通，**每一环都要下一环才生效**，链条强耦合 → P1 不成立。

## 5. 反模式清单（出现即判结构缺陷）

| # | 反模式 | 为什么错 | 修法 |
|:---:|:---|:---|:---|
| A-1 | **全案后置**：前 N-1 天讲方法、最后做全案 | 学员长期见不到全貌，无法形成心智模型；知识无处挂载 | 每个单元末加「回接」（见 §7） |
| A-2 | **阶段性重做**：同一任务类型在多个单元重复出现，无增量 | 学员判定「已通关又要重来」，动机崩塌（G-14） | 只改环境真实度 / 输入质量 / 学员角色（R-5） |
| A-3 | **伪实战**：号称实战，实为在干净数据上按模板填空 | 训练不出「扛得住」，只训练出「照着做」 | D4 起必须换脏数据/真客户 |
| A-4 | **part-task 泛化**：把复杂判断拆成小练习反复练 | 违背 4C/ID：part-task 只用于例行动作 | 复杂判断放回整体任务里练 |
| A-5 | **支架不撤**：全程给清单/模板/讲师兜底 | 独立度停在「在监督下做」，出不了门 | 每轮撤一档（清单→要点→无） |
| A-6 | **均分时间**：各段等分钟 | 权重失真（G-15） | 按「频率×关键性×难度」加权 |
| A-7 | **无迁移设计**：课上完就结束 | 迁移率默认极低（Brinkerhoff：约 15% 真正应用） | 6Ds D4/D5：管理者参与 + 在岗任务 + 间隔回炉 |
| A-8 | **评估错位**：考选择题、考笔记，不考表现 | 「通关」≠「能用」 | 真实性表现评估 + 量规 + 客户验收 |

## 6. 结构体检 8 问（定稿前机械过一遍）

1. 出口绩效卡的 5 个字段是否全部落字？（缺 → 假设版，标注）
2. 任务清单里「不可培训」的任务，是否已明确排除并写明原因？
3. 选的是哪个结构模式？**判别矩阵的哪一问给了这个答案**？（写不出 → 无依据）
4. 每个单元的标称阶段/任务类别是不是恰好 1 个？
5. 学员第一次见到**完整链路**是在第几个单元？如果是最后一个 → A-1。
6. 同一任务类型出现 ≥2 次时，增量（环境/输入/角色）写清楚了吗？
7. 各段时长的依据是什么？是否等于均分？
8. 课后 4 周内，学员至少有 3 次「被要求用」的机会吗？（无 → A-7）

## 7. 回接技术（Retro-Stitch）：零增时修掉 A-1

**问题**：强链式成果物 + 阶段块状 → 学员到末期才见全貌。
**做法**：把每个单元**已有的收尾/评议时段**改造成「回接」——不新增分钟，只改内容。

| 原来的收尾 | 改成 | 学员获得 |
|:---|:---|:---|
| 同行评议「本段产物好不好」 | 「把今天这一段接回整条链：**现在就要交付，还缺什么**」 | 全貌 + 缺口清单 |
| 半天总结「回顾要点」 | 讲师 15 min 演示极简全链（10 min 能跑完的玩具案例），学员 30 min 用自己的产物补一段 | 心智模型挂载点 |

判定：**每个单元结束时，学员能否用一句话说出「我这件东西在整条链的哪一环、下一步谁接」**。说不出 → 回接失败。

## 8. 评估升级：从「分数」到「可托付」

| 层 | 证据形态 | 说明 |
|:---:|:---|:---|
| L1 反应 | 满意度 | 只用于改进交付，不作质量证明 |
| L2 学习 | 表现评估（作品 + 量规） | 必须评「做出来的东西」，不评「记住的内容」 |
| L3 行为 | 在岗/客户现场留痕（真实使用记录、客户确认） | **训练营类项目的关键层**，缺此层就只是「上课」 |
| L4 结果 | 业务指标（周期、错误率、人效） | 通常需 1-3 个月，课前就要约定取数口径 |

EPA 四级可直接映射到关卡：G1「观察后能复述」→ G2「在监督下完成」→ G3「独立完成」→ G4/G5「能带别人做」。**关卡名不变，判据升级为「独立度」**。

## 9. 与商业约束的分离（最容易被忽略的一步）

顶级专家会把两件事分开说，而不是混成一句「最优方案」：

- **学习科学约束下的最优**：分散 > 集中（间隔效应）；在岗应用 > 课堂模拟；管理者参与 > 讲师单打。
- **商业约束下的最优**：客户只能给 5 天连排、学员只能脱产一次、预算只够 1 名讲师。

正确交付物是**两个方案 + 一句话取舍**：
> 「学习科学上最优是 3 天集中 + 3 次半月回炉；你的排期只能给 5 天连排，所以给你 5 天连排版（P2 螺旋 + 每日回接），并把 3 次回炉降级为课后 45 min×3 线上（不占课时，6Ds D4），代价是第 7 维达标率预计下降 X%（待试讲校验）。」

⛔ 不允许把「客户约束下的妥协」包装成「最佳实践」。**宣称最佳实践，必须同时给出被放弃的更优方案及放弃理由。**
