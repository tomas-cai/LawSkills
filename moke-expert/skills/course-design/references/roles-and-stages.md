# 角色 × 阶段：培训项目与磨课能力矩阵

> 适用：本专家包全部技能（L1 体系 / L2 项目 / L3 课程 / L4 课次 / L5 课堂）。
> 版本：1.9.0 新增。闭合缺陷 **G-19 角色失配** / **G-20 技能无依据宣称**；配套边界 **V-7**。
> 前置：层级定义见 `structure-levels.md`（L0-L6）。⛔ 未定层级不得查本矩阵。

---

## §0 本文件解决什么

**同一个专家，在不同阶段必须是不同的人。**

不是换称呼，是换**判据**：项目设计师的合格线是「客户签了、转化发生了」；课程设计师的合格线是「学员结业时能独立做出」；磨课师的合格线是「这一 90 分钟没有一分钟在浪费」。三条合格线互相冲突——项目设计师要按天卡死，课程设计师要留足练习时间，磨课师要砍掉多余内容。同一个人如果只戴一顶帽子干完全程，必然有一层被牺牲。

**不换帽的两种典型症状**（都真实发生过）：

| 症状 | 表现 | 代价 |
|:---|:---|:---|
| 用设计师的完美主义做项目决策 | 一门课打磨到第 7 版，整个项目排期崩了 | L2 失控 |
| 用项目设计师的排期思维做课堂设计 | 「这个活动给 15 分钟」，实际需要 40 分钟；按分钟切模块，不按学习曲线切 | L4/L5 空转 |

⛔ **判据：每进入一个阶段，先答一句「本阶段我主责哪个角色、此刻用哪两项核心技能」。答不出 = 角色失配。**

## §1 四个角色（不是四个 agent）

| 角色 | 层级 | 一句话职责 | 唯一产出 | 典型失败模式 |
|:---|:---:|:---|:---|:---|
| **课程体系架构师**<br>Curriculum Architect | L1 | 决定「要几门课、什么顺序、怎么认证」 | 课程地图 + 进阶路径 + 认证阶梯 | 把课程清单当体系（无先修关系、无认证出口） |
| **项目设计师**<br>Program Designer | L2 | 决定「一次干预怎么排：几天、几天上课、几天实战、谁到场、怎么转化、怎么评估」 | 项目方案 + 转化设计 + 评估方案 | 只设计课中，课前课后空白；或按「我们有几天」倒排内容 |
| **课程设计师**<br>Course Designer | L3 | 决定「这一门课分几个模块、每个模块练什么、怎么算过关」 | 课程大纲 + 材料包 + 考核标准 | 活动导向（热闹但不指向出口绩效）；把不可培训的任务当技能教 |
| **讲师／磨课师**<br>Instructor & Refiner | L4-L5 | 决定「这一次课每分钟怎么过、话怎么讲、卡在哪发」 | 分钟轴 + 讲师手册 + 工具卡 + 课件 | 把润色做成改内容；屏幕塞满字；示范跳过不演示 |

### §1.1 为什么是一个专家演四个角色，而不是四个 agent

三条理由，也可反用为「什么情况下该拆」：

1. **交接失真**：四个 agent 之间只能靠文件传话，而真实设计中最关键的往往是不写进文件的东西（「这个客户昨天说他们老板不认这个数」）。单专家共享上下文，损失最小。
2. **判断需要跨层反证**：项目排不下，往往不是排期问题，是课程设计太重；课程设计太重，往往不是模块问题，是任务清单把不可培训的任务算进来了。跨层反证要求同一个脑子。
3. **角色是视角，不是人格**：四角色共享同一套产物，只是照的灯不同。拆成四个 agent 会诱导「各管一段」，反而更容易在接缝处出错。

⛔ **但有一条不可省**：**每个角色的判据必须独立成表，不得互相代替**。「项目排期合理」不能推出「课程设计合理」，反之亦然。这就是为什么下面的 §3 给每个角色单列判据。

### §1.2 单人开发的「换帽声明」（必写，一句话）

小团队里一个人干四个角色的活是常态，此时唯一可行的防线是**显式声明切换**：

```
【换帽】现在从「项目设计师」切到「课程设计师」。
本阶段我不再问「几天够不够」，只问「结业时他能不能独立做出 X」。
上一角色留的未决项：<最多 3 条>。
```

⛔ 没有这句声明的直接后果：带着上一角色的 KPI 做下一角色的决策（最常见的是一次课被压缩到没有练习时间，因为「排期只剩 90 分钟」）。

## §2 RACI 矩阵（六阶段 × 四角色）

**A** = 主责（这一格的结论由他定，错了算他的）｜**R** = 执行｜**C** = 被咨询（必须听，可不采纳）｜**I** = 不介入

| 研发阶段 | 体系架构师 | 项目设计师 | 课程设计师 | 讲师／磨课师 | 本阶段唯一交付物 |
|:---|:---:|:---:|:---:|:---:|:---|
| **P00 需求发现**（该不该做） | C | **A / R** | I | I | `00-培训需求spec.md`（含「不该用培训治」的结论也合法） |
| **P01 分析**（出口绩效 + 任务 + 起点） | C | **A / R** | C | I | `01-需求定位报告.md` + 三张前置卡 |
| **P02a 项目架构**（L2：几天、怎么分、谁到场、怎么转化） | C | **A / R** | C | I | 项目架构方案（天 × 阶段 × 分钟 + 转化设计 + 评估设计） |
| **P02b 课程设计**（L3：模块、目标、考核） | I | C | **A / R** | C | `02-课程设计方案.md` |
| **P03 开发**（材料 + 课件 + 脚本） | I | C | **A**（内容）/ R | **A**（课堂落地）/ R | `03-教学材料包/` + 载体 |
| **P04 实施**（现场 + 转化推动） | I | **A**（转化）/ C | C | **A**（现场）/ R | `04-实施记录与反馈.md` + 转化台账 |
| **P05 评估**（L1-L4 + 是否升级体系） | C | **A / R** | C | C | `05-评估报告与迭代计划.md` |

### §2.1 三条读法（决定这张表怎么用）

1. **P02 必须拆成 a / b 两段，且 a 在 b 之前**。这是 G-18 的现场：先定「几天、哪些是课、哪些是实战」，再定「每门课分几个模块」。⛔ 顺序颠倒 = 用 L3 的模块去凑 L2 的天数，必然凑出「第 4 天不知道放什么课」。
2. **P03 有两顶帽子同时在场**（内容主责 + 课堂落地主责）。这不是矩阵失效，是真实约束：材料写得好但发不出去（工具卡断链）和课堂讲不完，是两个独立的失败。两者冲突时，**以磨课师的「能不能讲完」为硬约束，倒逼课程设计师删内容**，不得反过来延长课时。
3. **体系架构师全程只有 C，唯一例外是 P05 的「是否升级为体系」**。⛔ 单项目里体系架构师主责 = 过度设计（给 5 天项目建认证阶梯，没人用）。

### §2.2 交接单（每阶段结束必填，4 行，防失忆）

```markdown
## 角色交接单 · P0X → P0Y
- 产出物：<文件路径>（判据状态：过 / 有条件过（列条件）/ 降级（说明））
- 未决项：<谁在等什么，最多 3 条，写明「不等会怎样」>
- 给下一角色的硬约束：<不得违反的 1-3 条，如「M3 只有 45 min，不得加长」>
- 本阶段被否掉的方案：<1 条 + 否掉理由>（防止下一阶段原地复活）
```

⛔ **交接不得靠对话记忆**。跨会话续做时，先读交接单再动手。

## §3 四角色的能力栈（每角色 5 项 · 带判据与失效条件）

> **标注口径**：`[证据]` = 有对照研究或元分析支撑；`[惯例]` = 行业普遍采用但缺乏强证据；`[结构]` = 逻辑推演，无实证但可判定。⛔ 不得把 `[惯例]` 说成 `[证据]`。

### §3.1 课程体系架构师（L1）— 回答「要几门课、什么顺序、怎么认证」

| 技能 | 用来回答 | 可观测判据 | 失效条件 |
|:---|:---|:---|:---|
| 能力模型 / KSAO 拆解 `[结构]` | 岗位要的能力有哪几类 | 每个能力有 ≥2 条可观测行为描述，非形容词 | 能力项 >12 条 → 太碎，无法映射课程 |
| 任务 → 能力 → 课程 三级映射 `[结构]` | 每门课对应哪条能力 | 映射表无空行（无课支撑的能力 = 缺口；无能力支撑的课 = 冗余） | 一对一映射（一课一能力）→ 说明课太碎，可合并 |
| 先修关系与学习路径 `[结构]` | 谁先谁后 | 每门课写明「前置课 / 无前置」；存在环 = 错 | 全部无前置 = 其实是并列，不构成体系 |
| 认证蓝图与权重 `[惯例]`（参照 PMI/ATD 的 exam blueprint 做法） | 怎么算认证通过 | 各能力域权重合计 100%，且权重来源可追溯（任务频率或风险） | 权重均分 → 没有区分度，认证无意义 |
| 进阶阶梯与复训周期 `[结构]` | 初中高怎么分、多久回炉 | 每级有独立出口绩效，且「高级 ≠ 初级内容更多」 | 分级只靠课时长短 → 是同一门课切三段 |

⛔ **本角色的头号失败：把课程清单当体系**。判据一句话：**任意两门课之间说不出「谁是谁的前置」，这就不是体系，是课表。**

### §3.2 项目设计师（L2）— 回答「这一次干预怎么排、怎么保证用得上」

| 技能 | 用来回答 | 可观测判据 | 失效条件 |
|:---|:---|:---|:---|
| 绩效诊断（Mager & Pipe 式）`[结构]` | 这该用培训治吗 | 明确区分「缺知识 / 缺工具 / 缺权限 / 缺激励」，培训只治第一种 | 结论总是「需要培训」→ 未做诊断，只做了销售 |
| 出口绩效 + EPA 分级 `[证据]`（可托付活动，含独立度分级） | 结业时能独立做什么、谁验收 | 写出「产出物 / 完成条件 / ≥3 条可观测判据 / 验收人 / 独立度等级」 | 目标写成「了解 / 掌握 / 熟悉」→ 不可判定 |
| 6Ds 完整体验设计 `[结构]`（Define→Design→Deliver→Drive→Deploy→Document） | 课前课后各管什么、谁推动 | 六格全有内容；D4「推动转化」必须有**非讲师**的责任人 | 六格只剩 D3「交付」有内容 → 退化成排课 |
| 转化气候设计 `[证据]`（Holton 的转化系统：主管支持 / 问责 / 同伴） | 回岗后为什么用不上 | 写出 ≥2 条组织侧动作（主管任务单、周会回顾、同伴互查） | 全靠学员自觉 → 转化率按行业经验必然大幅衰减 |
| 评估四层 + 成功案例法 `[证据]`（Kirkpatrick / Brinkerhoff SCM） | 怎么证明有效 | L3（行为）有观测方式与观测人；L4 只承诺可归因的部分 | 只做 L1 满意度 → 不能指导迭代 |

⛔ **本角色的头号失败：只设计课中**。判据：**把「课中」从项目方案里删掉，方案还剩多少？剩不到一半，就还是课表。**

### §3.3 课程设计师（L3）— 回答「这门课分几个模块、怎么算过关」

| 技能 | 用来回答 | 可观测判据 | 失效条件 |
|:---|:---|:---|:---|
| 逆向设计 / UbD `[证据]` | 先定证据再定活动 | 每个模块有「评估证据」且证据形态 = 真实产出物（非选择题） | 先排活动再补目标 → 活动导向 |
| 整体任务 + 任务类别 + 支架递减 `[证据]`（4C/ID，van Merriënboer） | 用几个整体任务承载、支架怎么撤 | 学员首次见完整链路不晚于倒数第二个单元；支架逐轮撤除有记录 | 拆成互不相关的碎片练习 → 学员没见过全貌 |
| 首要教学原理 `[证据]`（Merrill：问题中心 / 激活 / 示范 / 应用 / 整合） | 这个模块缺哪一环 | 五要素缺一即标注缺口；「示范」必须是**展示怎么做**，不是讲要点 | 只有「讲 + 练」，无示范无整合 |
| 认知负荷与工作样例 `[证据]`（Sweller CLT；worked example → fading） | 新手为什么学不会 | 新手阶段先给完整样例再给半成品；单屏新信息 ≤5 条 | 一上来就开放式任务 → 认知过载 |
| 任务可培训性判定 `[结构]` | 这条任务该不该占课堂时间 | 逐条标注「可培训 / 只能识别与求助 / 不教」；不可培训项在课堂上只教判断与转交 | 把无权限、无接口、低频高风险的任务当技能教 |

⛔ **本角色的头号失败：活动导向**。判据：**任意一个活动，若删掉后出口绩效判据仍能达成，就该删。**

### §3.4 讲师／磨课师（L4-L5）— 回答「这几十分钟怎么过」

| 技能 | 用来回答 | 可观测判据 | 失效条件 |
|:---|:---|:---|:---|
| 教学事件序列 `[证据]`（Gagné 九事件） | 一节课的骨架 | 九事件映射到分钟轴，缺失项说明理由 | 只有「讲 → 练 → 总结」三段 |
| 反馈设计 `[证据]`（Hattie：反馈效应量中等偏上，但强依赖类型——过程/自我调节型优于人格表扬型） | 学员怎么知道差在哪 | 每次演练有「对照判据的具体差距」；表扬不替代差距 | 只给「很好 / 再想想」→ 无效反馈 |
| 示范与演练设计 `[证据]`（示范 → 引导练习 → 独立练习；刻意练习需即时反馈与重复） | 讲师怎么演、学员怎么练 | 关键动作有逐字示范脚本；练习轮次 ≥2 且难度递进 | 只讲不演 → 学员复制不了 |
| 认知负荷与上屏纪律 `[证据]`（Mayer 多媒体原则：冗余 / 分段 / 信号） | 屏幕上放什么 | 单页一个核心结论；不念屏；字不叠图 | 整页文字照读 → 双通道互相干扰 |
| 场域与临场应变 `[惯例]`（提问层次、走位、时间盒、超时降级预案） | 现场失控怎么办 | 每个长活动有「超时 10 分钟」降级方案；≥3 条兜底话术落字 | 只有 Plan A，无降级 |

⛔ **本角色的头号失败：把润色做成改内容**。判据：**润色版不得改变任何一条学习目标或考核判据**；需要改，退回课程设计师。

## §4 阶段门禁（Gate）

每阶段出口过三闸，任何一闸未过不得进入下一阶段：

| 闸 | 问题 | 未过的处理 |
|:---:|:---|:---|
| **G-α 判据闸** | 本阶段交付物的判据是否逐条可观测？ | 不可观测 → 重写判据，不得靠「基本达标」放行 |
| **G-β 归属闸** | 本阶段产出是否只属于本阶段？有无越界做下一阶段的事？ | 越界 → 移出，登记到交接单未决项 |
| **G-γ 依据闸** | 关键选择（结构模式 / 时长权重 / 载体形式）是否写出了依据？ | 无依据 → 标「假设版」，首页声明，不得宣称最佳实践 |

## §5 技能路由（本专家包 6 个技能 × 角色 × 阶段）

| 技能 | 主责角色 | 覆盖阶段 | 不管什么 |
|:---|:---|:---|:---|
| `course-discovery` | 项目设计师 | P00 | 不做结构设计、不排期 |
| `program-design`（v1.9 新增） | 项目设计师（P05 联体系架构师） | P01 协作 / **P02a** / P04 转化设计 / P05 评估设计 | ⛔ 不定模块、不写分钟轴、不碰课件 |
| `course-design` | 课程设计师 | P01 协作 / P02b / P03 内容 | ⛔ 不定天数、不排实战占比、不做 L1 体系 |
| `course-practice-project-evaluator` | 课程设计师 + 项目设计师 | P02b↔P03 之间门禁 | 不改写方案，只出立项结论 |
| `course-polish` | 讲师／磨课师 | P03 末 / P04 前 | ⛔ 不改目标、不改考核判据 |
| `course-review` | **四角色分别评审**（维度 10，横向） | 任意（交付前必做） | 不代做设计，只出发现与待办；⛔ 不得用一套通用判据评到底 |

⛔ **路由判据一句话**：问「几天 / 实战占几天 / 客户哪天来 / 怎么证明有效」→ `program-design`；问「这门课分几个模块 / 怎么考」→ `course-design`；问「这 90 分钟怎么过」→ 材料已定则 `course-polish`。

## §6 规模分档（防止过度工程）

⛔ 不是所有任务都要跑全矩阵。分档判据是**出口绩效是否含「在岗独立完成」**：

| 档 | 触发条件 | 上哪些角色 | 可省略 |
|:---:|:---|:---|:---|
| **S 单课** | ≤2 天、无客户现场、无结业答辩 | 课程设计师 + 磨课师 | 体系架构师全免；项目设计师只做 P00 一句结论；三张卡只做「出口绩效」 |
| **M 多天项目** | ≥2 天，或含实战 / 客户现场 / 答辩 | 四角色全上（体系架构师仅 C） | 不得省略任何一闸 |
| **L 体系** | ≥3 门课且有进阶关系（含认证 / 复训） | 四角色 + 体系架构师转 A | 不得省略认证蓝图与先修关系 |

⛔ 反向陷阱：**把 S 档当 M 档跑** → 一门 2 小时的课被要求写项目架构方案，用户会立刻觉得流程重。**把 M 档当 S 档跑** → 就是我们这次犯的错（5 天项目按「几门课拼起来」做）。

## §7 检查 6 问（定稿前逐条答，答不出即返工）

1. 本项目属于 S / M / L 哪一档？依据是什么？
2. 当前阶段主责哪个角色？我此刻用的两项核心技能是什么？
3. 本阶段交付物的判据是否逐条可观测？有没有「基本达标」这类放行话？
4. 有没有越界做下一阶段的事（P02a 做了 P02b 的模块拆分？P03 改了目标？）
5. 关键选择（结构 / 时长 / 载体）的依据写在哪一行？
6. 交接单填了吗？未决项有没有「不等会怎样」？

## §8 边界

- `角色齐备 ≠ 视角真切换`（V-7）：四个人在场而判据互相顶替，等于一个人干。
- `技能顶尖 ≠ 场景适配`：4C/ID 用在一门 60 分钟的合规课上是过度设计；6Ds 用在单课上是杀鸡用牛刀。
- `[惯例]` 不得冒充 `[证据]`：BOPPPS、70-20-10 之类是行业惯例，可以说「常用」，不能说「被证明」。
- 本矩阵只保「**不错位**」，不保「**最优**」——最优依赖真实任务清单、学员前测、试讲数据；缺输入时按 G-γ 标「假设版」。
