# 磨课 · 培训项目架构（L2）

## 这个技能管什么，不管什么

⛔ **本技能与 `course-design` 的边界是结构性硬边界，不是分工偏好**。混用的直接后果：用 L3 的课程模块去凑 L2 的项目天数，于是「天数用完了，内容还没完」，最后两天不知道该放什么课（缺陷 G-18 / G-16 的真实成因）。

| 问题 | 归本技能（L2） | 归 `course-design`（L3） |
|:---|:---:|:---:|
| 排几天、每天几小时 | ✅ | ❌ |
| 几天上课、几天实战、几天答辩 | ✅ | ❌ |
| 客户哪天到场、到场做什么 | ✅ | ❌ |
| 课前预习 / 课后回炉怎么设计 | ✅ | ❌ |
| 谁推动回岗转化、主管做什么 | ✅ | ❌ |
| 用什么证据证明有效（L1-L4） | ✅ | ❌ |
| 这门课分几个模块、模块顺序 | ❌ | ✅ |
| 每个模块的目标、练习、考核判据 | ❌ | ✅ |
| 逐页蓝图、课件、讲师手册 | ❌ | ✅ |

**一句话判据**：问「几天 / 谁到场 / 怎么证明有效」→ 本技能；问「这门课分几块 / 怎么考」→ `course-design`；问「这 90 分钟怎么过」→ `course-polish`。

---

## 前置：先定层级与规模

1. **层级**：读 `../course-design/references/structure-levels.md` 的 L0-L6 表，确认是 L2（一次有起止的干预）。⛔ 若用户其实要的是「多门课的进阶路径 + 认证」，那是 L1，先做课程地图，不在本技能范围（标注并转交）。
2. **规模分档**（读 `../course-design/references/roles-and-stages.md` §6）：
   - **S 档**（≤2 天、无客户现场、无答辩）→ ⛔ 不要跑本技能全流程，只回答「出口绩效卡」一句话结论即可，避免过度工程。
   - **M 档 / L 档** → 走完下面六步。

---

## 六步推导（顺序不可颠倒）

```
Step 1 出口绩效   →  结业时谁能在什么条件下独立做出什么？谁验收？
Step 2 任务清单   →  真实岗位里哪些任务值得占课堂时间？哪些不可培训？
Step 3 学员起点   →  他们现在会什么？有哪些错误概念？班内差距多大？
Step 4 结构模式   →  用 P1-P5 哪种？依据是判别矩阵的哪一问？
Step 5 时间与体验 →  天数怎么分？6Ds 六格各放什么？
Step 6 转化与评估 →  回岗靠什么机制？用什么证据算有效？
```

⛔ **从 Step 5 开始就是错**。凡以「我们有 5 天怎么排」开场的方案，一律退回 Step 1。

---

### Step 1 · 出口绩效卡（必落字）

```markdown
## 出口绩效卡
- 目标岗位/人群：<谁>，共 <N> 人，分 <M> 组
- 可交付产出物：<结业时必须交出的东西，名词，不是「能力」>
- 完成条件：<在什么资源 / 时限 / 信息条件下完成>
- 可观测判据（≥3 条）：
  1. <行为 + 标准，如「能对着原始资料说出 5 条可验证事实，其中 ≥2 条是客户没说出口的」>
  2. …
  3. …
- 验收人：<客户方谁签字 / 内部谁评审>
- 独立度等级（EPA）：<观察过 / 协助做过 / 可独立做 / 可教别人>
```

⛔ 写成「了解 / 掌握 / 熟悉 / 提升」→ 不可判定，退回重写。

---

### Step 2 · 任务清单卡（本技能最常被跳过、后果最大）

```markdown
## 任务清单卡
| 任务 | 频率 | 关键性（错了多贵） | 难度 | 可培训性 | 课堂处置 |
|:---|:---:|:---:|:---:|:---|:---|
| <任务名> | 每日/每周/每月 | 高/中/低 | 高/中/低 | 可培训 / 只能教识别与求助 / 不教 | 占 X min / 只讲判据 / 不占课堂 |
```

**排序规则**：`频率 × 关键性 ÷ 难度` 高者优先占课堂时间；**关键性高但频率极低**的任务只教「识别 + 求助路径」，不练全套；**不可培训**（无权限、无接口、无数据）的任务不进课堂，只进判据清单。

⛔ **头号错误：把不可培训的任务当技能教**。典型是「跨系统集成」「对外客户入口」——在中小企业里既没有 IT 支持也没有开放接口，课堂练 3 小时，回岗一次也用不上。

---

### Step 3 · 学员起点卡

```markdown
## 学员起点卡
- 已会（不必教）：<列 3 条，避免重复教学>
- 常见错误概念（≥3 条）：<错误做法 → 正确做法，用于设计冲突与示范>
- 班内差距：<最强 / 最弱差异，决定分组与配对策略>
- 前测方式：<10 分钟以内可完成的题 / 任务>
```

⛔ 没有错误概念清单 → 课堂无法设计「为什么这样是错的」，只能平铺直叙。

---

### Step 4 · 结构模式选择

五种模式、判别矩阵、8 条反模式、回接技术（Retro-Stitch）详见 `../course-design/references/program-structure.md`。

**最小判定表**（够用版）：

| 若…… | 选 |
|:---|:---|
| 各阶段产出物**彼此独立可用**，不依赖后续 | **P1 阶段块状** |
| 成果物**强链式**（前一环不完成，后一环无意义） | **P4 项目主线**（贯穿真实项目）+ **P2 整体任务螺旋**（同类任务多轮、支架递减） |
| 只有一个案例、由简到繁 | **P3 案例阶梯** |
| 线上 + 线下 + 在岗混合 | **P5 混合旅程** |

⛔ **「成果物强链式」是 P1 误用的总根源**——恰恰因为链式，才更该让学员**尽早**见全貌；越晚见全貌，越容易在中段失去方向。
⛔ 若必须用 P1（商业约束），**每个单元末必须做回接**：把本段产物接回整条链，产出「还差什么」清单。零增时，只改内容不改时长。

**定稿必答一句**：`本方案选 <模式>，依据是判别矩阵第 <Q?> 问的答案：<…>。` 答不出 → 首页标「**假设版结构**」，不得宣称最佳实践。

---

### Step 5 · 时间与体验分配（6Ds 六格）

先分天，再分格，最后才交给 `course-design` 排模块。

```markdown
## 天级排期
| 天 | 单元（标称阶段，恰好 1 个） | 内容 | 分钟 | 认知负荷 |
|:---:|:---|:---|:---:|:---|

## 6Ds 六格检查
| 格 | 内容 | 责任人（不得全是讲师） |
|:---|:---|:---|
| D1 Define 定义业务结果 | <业务指标 + 验收人> | 客户方 |
| D2 Design 设计完整体验 | <课前/课中/课后/实战> | 项目设计师 |
| D3 Deliver 交付学习 | <课 + 实战> | 讲师 |
| D4 Drive 推动学以致用 | <主管任务单 / 周会回顾 / 同伴互查> | **直属主管 + HR** |
| D5 Deploy 部署绩效支持 | <工具包 / 清单 / 模板 / 答疑通道> | 项目设计师 |
| D6 Document 记录证据 | <L1-L4 证据来源> | HR |
```

⛔ **D4 的责任人不得是讲师**。全是讲师 = 没有转化机制，回岗三周即归零。
⛔ **单元（天 / 半天）只标称一个阶段**，单元内不得出现其他阶段的活动（`roles-and-stages.md` §2、`phase-02-design.md` 第六节）。
⛔ **时长依权重，不得均分**。实施类目标占比应高于认知类；给不出权重依据 → 按「出口绩效所需练习量 × 轮次」估算并写明。

---

### Step 6 · 转化与评估设计

**转化三件（缺一即标风险）**：
1. **回岗任务单**：结业后 2 周内必须完成的 1 件真实任务 + 提交物 + 审核人
2. **间隔回炉**：≥2 次线上短会（每次 45 min），间隔 1-2 周，只解决「回岗卡住的事」
3. **主管动作**：主管需完成的 2 件事（如批一次产出物、在周会上留 10 min）

**评估四层（只承诺可归因的部分）**：

| 层 | 证据 | 观测方式 | 观测人 |
|:---:|:---|:---|:---|
| L1 反应 | 相关性 / 投入度（不承诺满意度=有效） | 结业问卷 | 助教 |
| L2 学习 | 判据达成（对应出口绩效卡） | 通关评审 | 评审人 |
| L3 行为 | 回岗任务单完成质量 | 产出物抽检（≥2 周后） | 直属主管 |
| L4 结果 | 业务指标变化 | 只报趋势 + 干扰因素，**不单独归因** | 客户方 |

> 需要强归因时用 **成功案例法（Brinkerhoff SCM）**：找 2-3 个「明显用上了」和 1-2 个「完全没用」的样本做深访，比全样本问卷更能指导迭代。

## 边界

- `排期能加总 ≠ 架构正确`：天数对得上只过算术闸，结构归属另过一闸。
- `6Ds 六格填满 ≠ 转化发生`：D4 责任人不落到主管与 HR，等于没设计。
- 本技能只保「架构有依据、可判定、可审计」，不保「最优」；最优依赖客户真实任务数据、学员前测、试讲修正数据。缺输入时强制标「假设版结构」，**这本身是能力，不是缺陷**。
