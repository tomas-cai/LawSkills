# 微课设计 Skill

## 定位

把 `microcourse-planner` 的候选变成一个真正能独立完成的学习单元。设计重点不是“讲得少”，而是让学习者在短时间内完成一次认知、操作、判断或复习，并留下可验证的结果。

本 Skill 不写最终口播稿和逐镜脚本；它产出供 `microcourse-scriptwriter` 和 `microcourse-producer` 使用的教学蓝图。

## 前置检查

优先读取：

- `06-微课补充包/00-微课补充地图.md`；
- `02-课程设计方案.md`；
- 来源课时的大纲、学员手册、讲师手册和测评方案；
- 主课当前版本和目标编号。

如果候选没有 `Approved` 状态，先指出需要确认，不直接把它写成定稿设计。

## 设计流程

### 1. 固定微课边界

先写清楚：

| 项目 | 要求 |
|---|---|
| 学习者 | 具体到基础、场景和当下任务 |
| 学习目标 | “能够 + 行为动词 + 内容 + 证据” |
| 核心问题 | 学完后解决的唯一问题 |
| 时长 | 2–15 分钟，含练习和反馈 |
| 先决条件 | 学习者必须已经知道或准备好的内容 |
| 完成证据 | 答案、判断、操作结果、作品或一句迁移计划 |
| 不包含 | 明确排除的知识、讨论和复杂任务 |

学习目标示例：

- 不合格：“了解提示词的写法”；
- 合格：“能够把一个模糊需求改写为包含对象、约束和验收标准的提示，并通过三项检查”。

### 2. 选择微课结构

根据类型选择主结构，不要强行套用同一模板：

| 类型 | 推荐结构 | 默认时长 |
|---|---|---:|
| 概念解释 | 痛点 → 例子 → 核心规则 → 快速回忆 → 应用提示 | 2–5 分钟 |
| 操作演示 | 目标结果 → 环境 → 步骤 → 常见错误 → 学员复做 | 5–12 分钟 |
| 案例判断 | 场景 → 选项 → 独立判断 → 揭示依据 → 迁移 | 5–8 分钟 |
| 引导练习 | 任务 → 尝试 → 评分标准 → 反馈 → 重做 | 8–15 分钟 |
| 复习测验 | 回忆 → 作答 → 解释 → 错误标签 → 下一次使用 | 2–5 分钟 |
| 岗位支持 | 使用场景 → 清单/模板 → 示例 → 使用边界 | 2–5 分钟 |

### 3. 设计学习者动作

每节微课至少包含一次主动行为：

- 选择或排序；
- 写一句话或填一项；
- 在工具中完成一个动作；
- 识别错误并说明依据；
- 用模板产出一个最小结果。

只播放讲解、不要求学习者做任何事的内容，默认降级为“阅读资料”或“岗位参考”，不称为完整微课。

### 4. 管理认知负荷

- 一节微课最多引入 3 个新概念；
- 每 1–3 分钟发生一次视觉、问题或行为变化；
- 先给结果和使用场景，再补充术语；
- 一次只展示一个主要操作路径；
- 把例外、扩展和高级技巧移到“延伸阅读”；
- 复杂任务拆成多节微课，不用一个长视频解决。

### 5. 设计反馈与迁移

反馈至少说明：答案是什么、为什么、错在哪里、下一次怎么做。结尾必须有一个与主课或工作场景连接的迁移动作，例如：

> 回到第 3 课的项目中，用本节检查表重新审阅你的需求，并记录一处修改。

## 交付格式

在 `06-微课补充包/01-微课单元设计/` 下为每个 `MC-ID` 建立设计单，建议命名为 `MC-01-主题-微课单元设计.md`。

必须包含：

1. 来源追踪和版本信息；
2. 学习者、先决条件和使用时机；
3. 一个学习目标和完成证据；
4. 类型、时长和媒介选择；
5. 按时间段排列的学习流程；
6. 学习者动作、反馈和评分标准；
7. 主课衔接和不重复边界；
8. 无障碍、更新和风险说明；
9. 本单元完成检查与 Changelog。

详细模板见 `references/unit-design-framework.md`。

完成后，将设计单交给 `microcourse-scriptwriter`，并保留 `MC-ID` 不变。
