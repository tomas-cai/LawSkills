# 微课规划 Skill

## 定位

把主课程中的学习阻塞点转化为可独立完成的微课候选。微课不是按章节切短的录播课，而是围绕一个明确的学习目标、动作或判断，补强主课的学习旅程。

本 Skill 只负责“做什么微课、为什么做、什么时候做、做到什么程度”，不负责写口播稿、制作媒体或最终质量评审。

## 输入与入口

优先读取课程项目中的以下文件：

1. `00-培训需求spec.md`：目标人群和业务问题；
2. `01-需求定位报告.md`：能力差距、学习者痛点和先决条件；
3. `02-课程设计方案.md`：学习目标、模块、活动和测评对齐；
4. `03-教学材料包/00-课程大纲.md`：课时、主题、内容范围和时长；
5. `03-教学材料包/01-学员手册.md`、`02-讲师手册.md`、`04-测评方案.md`：重复解释点、常见错误和证据要求；
6. `04-实施记录与反馈.md`、`05-评估报告与迭代计划.md`：真实学习困难和课程改进方向。

如果只有课程大纲，仍可先做候选规划，但必须标注“基于大纲推断”，不能把候选直接当成已验证需求。

## 规划流程

### 1. 建立主课基线

记录课程名称、版本、目标学员、主课目标、课时结构、学习活动、测评方式和当前交付状态。为每个候选保存来源课时、来源目标编号和来源文件版本。

### 2. 找出微课机会

从以下信号中提取候选：

| 信号 | 适合的微课方向 |
|---|---|
| 学员缺少先决知识 | 课前补齐型 |
| 讲师每次重复解释同一概念 | 概念解释型 |
| 工具操作步骤固定且容易忘 | 操作演示型 |
| 学员对一个判断标准反复犯错 | 案例判断型 |
| 课后无法把方法迁移到工作 | 迁移练习型 |
| 需要多次检索和回忆 | 复习测验型或岗位支持型 |

同时记录主课中的互动、讨论、复杂实践和讲师即时反馈。它们通常不应被拆成微课。

### 3. 应用筛选门槛

每个候选按 0–4 分评估：

| 维度 | 评估问题 |
|---|---|
| 学习价值 | 是否解决真实且高频的学习阻塞？ |
| 主课互补性 | 是否补充主课，而不是重复主课？ |
| 微课适配度 | 能否在一个目标和一次学习行为内完成？ |
| 证据可得性 | 学完后能否通过答案、作品、操作或判断证明？ |
| 维护成本 | 主课或工具变化后是否容易更新？ |

总分 16 分以上进入“建议开发”，12–15 分进入“待验证”，11 分以下暂不开发。若涉及安全、隐私、版权或工具高风险变化，即使分数足够，也必须标注风险。

### 4. 安排在主课旅程中的位置

用以下顺序安排：

- 课前：补先决知识、环境准备、问题预热；
- 课中间隙：只放置可独立观看的概念或示范，不替代关键讨论；
- 课后：巩固、测验、错误纠正和迁移任务；
- 岗位使用：模板、清单、决策卡和快速参考。

### 5. 形成微课补充地图

在课程项目根目录创建或更新 `06-微课补充包/00-微课补充地图.md`。每个候选至少包含：

- `MC-ID`、微课标题和类型；
- 来源课时、来源目标、来源版本；
- 主课阶段和微课用途；
- 一个可观测学习目标；
- 推荐时长和媒介形式；
- 先决条件与后续主课活动；
- 评分、开发优先级和验证计划；
- 对主课的互补说明与不做什么。

## 硬性边界

- 不按幻灯片数量平均切分课程；
- 不把一节直播课压缩成一段长视频；
- 不在一节微课中同时塞入概念、演示、开放讨论和综合项目；
- 2–15 分钟是默认范围，超过 15 分钟必须说明拆分或保留主课的理由；
- 每节微课只保留一个主要目标和一个完成证据；
- 不改变主课目标，不自行删除主课内容；
- 候选规划与已批准开发必须区分状态：`Candidate`、`Approved`、`Draft`、`Final`、`Superseded`。

## 交付格式

使用 `references/planning-framework.md` 的模板生成 `00-微课补充地图.md`。文件末尾必须有：

1. 本轮规划结论；
2. 建议先开发的 3–5 节微课；
3. 暂不适合微课的主课内容；
4. 需要用户确认的假设；
5. Changelog。

完成规划后，将已批准的 `MC-ID` 交给 `microcourse-designer`，不要直接跳到脚本或媒体制作。
