# 写作润色与质检

把“是否达标”和“如何改进”分开。先判断问题类型与严重程度，再决定是局部润色、回退大纲，还是要求 writer 重写。

## 输入检查

读取 `draft.md`，尽量同时读取 `outline.md`、`content-analysis.md/json` 和 `style-rules.json/style-guide.md`。先建立六格需求卡，确认目标平台、篇幅、发布标准和是否允许改动结构。

缺少分析或来源文件时，只能检查文本内部一致性，并在报告中声明“事实无法外部核验”。不要因为缺少背景就自行替作者补事实。

## 工作流程

1. 建立问题登记表，按 `P0` 阻断交付、`P1` 需重写、`P2` 建议修正、`P3` 可选优化分级，并记录位置、问题、依据、建议。
2. 做结构质检：中心承诺、读者收益、章节顺序、论点—证据、重复、跳跃、开头吸引力、结尾闭环、CTA 和平台要求。
3. 做事实质检：数字、时间、人物、原话、因果、比较、绝对化表述、来源标记。发现不确定项时标 `NEEDS_SOURCE`，不擅自改成确定事实。
4. 做语言质检：语病、错别字、标点、指代、句式、段落节奏、术语一致性、风格规则、AI 套话和过度营销。
5. 先生成 `proofread-report.md`，再依据报告生成 `revised-draft.md`。P0/P1 若需要结构或事实重建，保留问题并把结论写为 `REWRITE_REQUIRED`，不要用表面润色掩盖。
6. 对所有实质性改动给出“改动类型”和理由；删除原话、改写数字或改变结论时必须保留原文对照或明确标注，交由人工确认。

## 产物契约

`proofread-report.md` 至少包含：

- 总结结论：`PASS`、`PASS_WITH_NOTES` 或 `REWRITE_REQUIRED`
- 评分/状态：结构、事实、逻辑、语言、风格、平台适配
- 问题表：级别、位置、原文、问题、依据、建议、是否已修复
- 未解决事项、需要用户确认的决策和返工路径

`revised-draft.md` 保持原有内容边界，包含：

- 经过修正的完整稿件
- 必要的 `[待核实]`、证据 ID 和图片占位符
- 不在正文中写审校意见；审校意见只放报告

## 不同问题的处理

| 问题 | 处理 |
|---|---|
| 错别字、标点、明显语病 | 直接修正并登记 |
| 冗余、节奏、衔接 | 在不改变含义时局部修正 |
| 论据不足、结构跳跃 | 报告并建议回到 outline/writer |
| 数字、原话、因果无法确认 | 标记待核实，不替换成猜测 |
| 风格与清晰度冲突 | 优先清晰和事实准确，记录取舍 |

## 交付前检查

- [ ] 质检报告先于修订稿生成。
- [ ] 已区分结构问题、事实问题和语言问题。
- [ ] 没有静默改变主旨、事实、数字、人物立场或原话。
- [ ] P0/P1 问题没有被“润色”掩盖。
- [ ] 修订稿可独立阅读，报告可追溯每个关键改动。
