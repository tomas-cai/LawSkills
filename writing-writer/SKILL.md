# 写作初稿生成

按照大纲施工，按照素材写事实，按照风格写表达。先完成结构和信息兑现，再处理句子美感；不要在写作阶段偷偷扩写素材没有提供的背景。

## 输入检查

先建立六格需求卡并加载：

1. `outline.md`：文章结构与段落任务；
2. `content-analysis.md` 或 `.json`：事实、证据、原话和风险；
3. `style-rules.json`，必要时再读 `style-guide.md`：风格规则与示例；
4. 用户补充的字数、平台、标题、SEO、CTA、格式和隐私要求。

缺少关键输入时，列出缺失项并采用最小假设继续：可以写“待补段落”或 `[待核实：...]`，不得编造。若用户只给主题而没有素材，明确这是“从零创作”而不是“素材写作”。

## 工作流程

1. 建立写作矩阵：将大纲每个章节映射到观点、证据 ID、字数预算、风格要求和风险。
2. 先写标题、开头和结尾，确认中心承诺一致，再逐节展开；每节先兑现大纲中的任务，再补充转场和例子。
3. 使用来源标记或脚注占位追踪事实。原话只在素材明确允许时引用，不能把概述改造成引号中的精确原话。
4. 应用风格规则：硬约束优先，软偏好其次；当风格与事实清晰度冲突时，优先事实清晰度。
5. 做一次“内容审计”：检查字数、章节覆盖、事实状态、数字、因果、标题承诺、CTA、禁用词和平台格式。
6. 输出 `draft.md` 与 `draft-meta.json`。需要多版本时，保持相同事实底座，只改变结构或表达策略，并分别命名。

## 产物契约

`draft.md` 包含：

- 标题、导语/摘要、正文、结尾/CTA
- 必要的 `[F03]`、`[Q02]` 或 `[待核实]` 标记
- 图片位占位符，例如 `<!-- IMAGE-01: 章节/用途 -->`
- 不把写作说明、内部推理或未确认信息混入面向读者的正文

`draft-meta.json` 至少包含：

```json
{
  "version": "1.0",
  "title": "",
  "word_count": 0,
  "target_word_count": null,
  "format": "markdown",
  "used_evidence_ids": [],
  "unresolved_items": [],
  "style_rules_applied": [],
  "image_placeholders": [],
  "self_check": {"outline_coverage": true, "fact_traceability": true, "needs_proofreading": true}
}
```

## 写作原则

- 不补写姓名、数字、时间、因果、引用和结论。
- 不为了“像人”而添加虚构经历、感受或对话。
- 不重复大纲标题；用段落承担信息任务。
- 把抽象概念落到读者可理解的场景、判断或动作。
- 避免模板化开场、空泛总结、无证据的“大家都知道”和过度承诺。

## 交付前检查

- [ ] 中心承诺在开头、正文和结尾一致。
- [ ] 每个大纲章节都有实际内容或明确解释为何删除。
- [ ] 每个关键事实可以回溯到分析文件的证据 ID。
- [ ] 目标字数、格式、禁用词和平台要求已满足。
- [ ] 已把需要 proofreader 处理的事项写入元数据。
